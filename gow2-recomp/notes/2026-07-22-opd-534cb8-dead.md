# OPD `0x00534CB8` (→ `func_0032854C`) — sem caller (2026-07-22)

## Pergunta

Quem carrega/chama o OPD factory do micro-ctor schedule?

## Estático (EBOOT + lift)

| Teste | Resultado |
|-------|-----------|
| `bl` / `b` → `0x0032854C` | **0** |
| `bl` → siblings `328B08/978` | **0** (só internos; sem OPD próprio) |
| `bl` → `00329490` | **2** (ambos **dentro** da família `3286AC`/`328C74`) |
| literais BE `0x00534CB8` / `0x534CB8` | **0** |
| `lis`+`addi` materializando OPD/code | **0** |
| TOC-rel `r2 + (-0xC4C0)` → OPD | **0** |
| OPD no EBOOT | **sim** `file+0x524CB8` code=`0x32854C` toc=`0x541178` |
| OPD `0x534CC0` → `328B18` | existe |
| OPD `0x534D70` → `329490` | existe |
| Callers directos no lift a `0032854C` | **0** |

Conclusão estática: o root **não tem aresta de entrada** no grafo de código.
Não é fallthrough tipo 2550C8; é **função órfã** nesta imagem para o caminho de boot.

## Runtime (pós-R_Perm)

| Probe | N |
|-------|--:|
| `[MC-32854C]` … família | **0** |
| `[OPD-ICG]` com code/OPD do cluster | **0** |
| `[MC-SCAN]` ptrs em heap/data (fora `.opd`) | **0** |
| `[MC-SCAN]` na casa do OPD `0x534CB8` | 1 (o próprio code word — ignorado) |
| `[TYMAP-DUMP]` | 1 (typemap vivo, path **ortogonal**) |

Log: `/tmp/vdec_mc_scan.log`.

`[MC-SCAN]` (gated `PS3_TRACE_MC` / `A1CHAIN`): varrimento read-only de janelas
guest após R_Perm full; procura `0x534CB8` / `0x32854C` / `0x534D70` **fora** da
secção OPD. **hits=0** → ninguém regista o factory em runtime nesta janela.

## Veredito

| Hipótese | Estado |
|----------|--------|
| Site `bl`/OPD literal ainda não encontrado | **Refutada** (censo completo) |
| OPD copiado para heap no boot | **Refutada** (MC-SCAN 0) |
| Família entra mas probes falham | **Refutada** (marcadores no binário; entry 0) |
| **Código morto / não agendado neste boot** | **Confirmada** |
| Typemap walk espera este path | **Incompatível com H3** — typemap já existe sem esta família |

O walk A1 depende de `0032E200` ← … ← `00329490` ← … ← **`0032854C`**.  
Como **`0032854C` nunca é referenciado**, o menu/cena que passaria por este
factory **não está no grafo vivo** do boot actual (legal → intro → WADs).

## Implicação de produto

- **Não** há “um `bl` a descomentar” para destravar o schedule.
- Desbloquear menu natural exige **outro** pipeline (UI que encha VRAM, outro
  factory, progressão FSM que *passe a referenciar* este OPD em fase mais
  tardia) — ou provar num boot mais longo/outro state que o OPD aparece.

## Código

- `patch_mc_schedule_probe.py` — entry `[MC-*]`
- `ppu_loader.cpp` — `[OPD-ICG]` alargado; `[MC-SCAN]` pós-R_Perm
