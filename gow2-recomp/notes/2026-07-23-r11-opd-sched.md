### B94EC is not a schedule entry

Lift + binary: `func_000B94EC` is an **epilogue fragment** (`ld r0,0xA0(r1)` …) that **always** trampolines to `B6150`.  
It is only reachable as the **dead second trampoline** after `B94D4` live → `B7888` (lifter fallthrough pattern; first branch returns).  
**No OPD, no data word, no addis+addi materialization** of `0xB94EC` or a parent OPD.

### B6150 OPD is orphan

- Present in master OPD cluster next to neighbors (`B60DC`…`B6228`…).
- **Zero** static data pointers to `0x51D7A0` (unlike BB414 in table `0x510000+`).
- **Zero** text sequences materializing `0x51D7A0` / `0xB6150` via lis/addis+addi/ori.
- Lift call-sites: only dead `B94EC→B6150`, registry `030`, and internal `B6150→B61F4` gate.

### B61F4

- **No OPD.** Only live edge: `B6150` if `*( *(TOC-0x62B0) + 0x1CC ) == 0`.

### Selector table note

`0x510004…` is a sparse OPD **export/selector** table. Slot `0x510054` = BB414 (explains R10 enter 1× → BB37C). **B6150/BB424 are not in this table.**

**Conclusão OPD:** não há schedule estático/dynamic-offline para o menu arm. Entry real exigiria **instalação runtime** do OPD `0x51D7A0` (ou ctr=`0xB6150`) que **nunca** ocorre in-boot (tot=0 + zero ICALL hits).
