# Requirements: v1.2 — Toolchain Go (PoC com parity)

**Defined:** 2026-08-02  
**Status:** **QUEUED** — não é o marco activo. Activo = **v1.1** (boot / walls).  
**Core Value (herdado):** recompilação **reproduzível** a partir do binário; tooling novo não pode piorar isso.

## Contexto e decisão de escopo

A toolchain actual em `tools/*.py` (~23k LOC no motor) é **quase só stdlib**. Migrar para Go é viável, mas:

- **Não** acelera walls D/E no hot path do runtime.
- **Não** substitui o plano Xenon (midasm / switch tables / weak) — esse continua em Python/C até decisão de re-port.
- **Sim** pode dar binário único, disasm/lift mais rápido, e tipos mais rígidos **se** a parity com Python for prova formal.

Este marco é um **PoC com gates de parity**, não um big-bang “apagar Python”.

**Ativar o marco:** só após fecho (ou pausa explícita) do v1.1, **ou** via workstream paralelo se o usuário pedir — sem roubar o `STATE.md` do boot.

## v1.2 Requirements (in scope)

### Scaffold e contrato CLI

- [ ] **GO-01**: Existe módulo Go versionado em `tools/go/` (ou `cmd/` na raiz) com `go.mod`, `README` e build `go build ./...` em macOS/arm64 e linux (local ou CI).
- [ ] **GO-02**: Cada comando Go expõe CLI **compatível o suficiente** com o script Python que substitui (mesmos flags críticos documentados; exit codes 0/1/2 com semântica estável).
- [ ] **GO-03**: Documentação em `docs/TOOLS_GO.md` (ou secção em `docs/TOOLS.md`) descreve o que está em Go, o que fica em Python, e como correr parity.

### Parity disasm / ELF (fundação)

- [ ] **GO-04**: `ppu-disasm` (Go) produz, para fixtures sintéticas **e** para um corpus de palavras extraídas do EBOOT GoW2 (sem commitar o ELF), o **mesmo mnemonic/operands** que `tools/ppu_disasm.py` em ≥99,9% das palavras do corpus (falhas listadas e classificadas: bug Go vs Python vs inválido).
- [ ] **GO-05**: `elfinfo` (Go) reporta entry, machine, número de segments/sections e lista de imports (NID) alinhada a `elf_parser.py --json` no mesmo EBOOT local (diff estrutural, não text dump completo).
- [ ] **GO-06**: Suite `go test ./...` cobre decode de famílias de opcode que já falharam no passado (VMX pack, RLD form, invalid skip) com casos portados de `tools/test_*.py` relevantes.

### Function bounds e lift (PoC, não 52k funcs)

- [ ] **GO-07**: `find-functions` (Go) em modo OPD-seed, sobre o EBOOT local, atinge **recall ≥95%** do conjunto de starts de `functions.json` actual (ou do oráculo Ghidra se documentado) num relatório JSON; misses listados.
- [ ] **GO-08**: `ppu-lift` (Go) emite C **semanticamente equivalente** a `ppu_lifter.py` para um **conjunto golden** de N funções (N≥20, incluindo ≥1 com branch, ≥1 com load/store, ≥1 com trampoline/tail) — aceite por: (a) compile do harness sintético **ou** (b) diff normalizado do C + selftest existente adaptado.
- [ ] **GO-09**: Benchmark documentado: tempo disasm+lift do golden set em Python vs Go (mesma máquina); Go **não pior** que Python no golden; meta aspiracional ≥2× no disasm-only.

### Gates de não-regressão do produto

- [ ] **GO-10**: Enquanto o Go não for o emissor default, **zero** mudança obrigatória no path de build `boot_gow2` / smoke v1.1 — o PoC é opt-in (`PS3_LIFT_ENGINE=go` ou flag CLI).
- [ ] **GO-11**: Um job ou script `tools/go/parity_gate.sh` (ou `go test` + script) falha se a parity disasm do corpus cair abaixo do limiar GO-04.
- [ ] **GO-12**: Veredicto escrito em `.planning/milestones/v1.2-VERDICT.md`: **PROMOTE** (continuar SPU/lifter full) / **HOLD** (manter Python) / **HYBRID** (só disasm/analyse em Go), com números.

## Out of Scope (explícito)

| Feature | Reason |
|---------|--------|
| Reescrita do runtime C/ObjC/Metal | Go é **só** toolchain offline |
| “Walls caem mais rápido” como aceite | Aceite = parity + opt-in; walls = v1.1 / Metal |
| LLM a gerar o lifter Go | Mesma regra anti-forja do CLAUDE.md |
| Merge big-bang que parte cherry-pick upstream | Python lifter permanece canónico até PROMOTE |
| Activar opts ABI no lifter Go | Fora; independe da linguagem |
