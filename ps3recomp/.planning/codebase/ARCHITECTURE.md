# Architecture

**Analysis Date:** 2026-07-26

## System Overview

`ps3recomp` is a static recompiler: PS3 (Cell Broadband Engine) game binaries are
translated **ahead of time** into C/C++ that compiles into a native host executable
(Windows, macOS-arm64, Linux). There is no emulator/interpreter loop at runtime for
the PPU path — lifted guest code IS the host binary's code, once compiled.

```text
┌───────────────────────────────────────────────────────────────────────────┐
│  OFFLINE PIPELINE (Python, `tools/`)                                      │
│  EBOOT.ELF (pre-decrypted) ──▶ elf_parser ──▶ ppu_disasm/ppu_lifter       │
│  (+ spu_disasm/spu_lifter for embedded SPU images, extract_spu_images.py) │
│  driven by a recompiler `config/example.toml` (`recomp_config.py`)        │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ generates
                                ▼
┌───────────────────────────────────────────────────────────────────────────┐
│  GENERATED GUEST CODE (per-title, gitignored)                             │
│  `ppu_recomp_XXX.cpp` / `ppu_recomp.h`  (PPU functions as C++)            │
│  `spu_recomp.c` / `spu_recomp.h`        (SPU images as C, per test/job)   │
│  NID import table: `gow2_gen/ppu_hle_nids.cpp` (generated by              │
│  `tools/gen_hle_nids.py`, checked in for GoW2)                            │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ compiled + linked against
                                ▼
┌───────────────────────────────────────────────────────────────────────────┐
│  RUNTIME LIBRARY  `libps3recomp_runtime.a`  (CMake target, this repo)     │
│  ┌─────────────────────┐  ┌─────────────────────┐  ┌────────────────────┐ │
│  │ PPU execution model │  │ SPU execution model │  │ Memory / syscalls  │ │
│  │ `runtime/ppu/`      │  │ `runtime/spu/`      │  │ `runtime/memory/`  │ │
│  │ ppu_context, loader,│  │ spu_context, DMA,   │  │ `runtime/syscalls/`│ │
│  │ giant lock, guest   │  │ channels, workload  │  │ vm.h, lv2_syscall  │ │
│  │ ELF loading         │  │ jobs                │  │ table              │ │
│  └─────────────────────┘  └─────────────────────┘  └────────────────────┘ │
│  ┌────────────────────────────────────────────────────────────────────┐   │
│  │ HLE firmware reimplementation  `libs/`                             │   │
│  │ cellGcmSys, cellVdec, cellFs, sysPrxForUser, cellSpurs, cellSync,  │   │
│  │ cellAudio, cellPad, cellSysutil, codec/font/network/misc modules...│   │
│  └────────────────────────────────────────────────────────────────────┘   │

│  │ Movie overlay: `movie_hle_*` contract — VideoToolbox+Metal / FFmpeg│   │
│  │ Audio: WASAPI (Win) / CoreAudio+SDL2 (POSIX); Pad: XInput/GameCtlr │   │
│  └────────────────────────────────────────────────────────────────────┘   │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ linked with per-game boot scaffold
                                ▼
┌───────────────────────────────────────────────────────────────────────────┐
│  PER-GAME NATIVE EXECUTABLE (games/gow2/, `../gow2-recomp` sibling repo)  │
│  `games/gow2/boot_macos.cpp` (macOS entry) / boot_v2_new.exe (Windows)    │
│  loads decrypted EBOOT.ELF into guest VM, calls `ppu_run`, drives the     │
│  present loop and HLE service threads                                     │

```

## Pattern Overview

**Overall:** Ahead-of-time (static) binary translation / recompilation, following the
same lineage as N64Recomp / UnleashedRecomp / PS2Recomp. Two clearly separated halves:
an **offline Python toolchain** that never runs at game runtime, and a **C/C++ runtime
library** that is compiled together with the *generated* guest code into one native
executable per game.

**Key Characteristics:**
- No JIT, no bytecode interpreter for the PPU hot path — lifted PPU functions are
  ordinary C++ functions operating on a `ppu_context*`.
- SPU currently defaults to an **interpreter** execution strategy per-image
  (`spu_backend = "interpreter"` in `config/example.toml`); SPU lifting to native C
  also exists (`tools/spu_lifter.py`) and produces `spu_recomp.c`, used by the SPU
  test harnesses under `runtime/spu/tests/`.
- Memory is a single flat guest address space (max 4GB, PS3 real: 256MB XDR + 256MB
  VRAM) mapped as `host_ptr = vm_base + guest_addr`; all guest memory access goes
  through big-endian-aware accessor macros (`runtime/ppu/ppu_memory.h`,
  `runtime/memory/vm.h`).
- HLE (High Level Emulation) is the default strategy for nearly all Cell OS modules
  (`[modules]` section of `config/example.toml`): PS3 library calls are matched by
  NID and redirected to hand-written C reimplementations in `libs/`, rather than
  recompiling the original PRX code (LLE, used selectively, e.g. `cellSpurs = "auto"`).
- Platform divergence is isolated behind narrow, explicit **vtable/contract
  abstractions** (`rsx_backend`, `movie_hle_*`) rather than `#ifdef`-per-callsite
  scattering; CMake conditionally includes platform-specific `.m`/`.c` files
  (`CMakeLists.txt` `if(APPLE)` block).
- Concurrency model is a **single giant lock** around all guest code execution
  (documented at length in `runtime/ppu/ppu_loader.cpp`), analogous to CPython's GIL —
  an explicit interim measure, not fine-grained per-structure locking.
- The monorepo hosts the engine at the root and per-title ports under `games/<title>/`,
  imported via `git subtree` from a per-title mirror repo (see Directory Layout below).

## Layers

**Offline lift/codegen tooling (`tools/`):**
- Purpose: turn a decrypted PS3 ELF into compilable C/C++ source, plus supporting
  analysis (function-boundary detection, jump-table recovery, PRX NID resolution).
- Location: `tools/` (Python, requires Python ≥3.11 per `pyproject.toml`, per
  CMake comment in `CMakeLists.txt`).
- Contains: `elf_parser.py`, `ppu_disasm.py`, `ppu_lifter.py`, `spu_disasm.py`,
  `spu_lifter.py`, `prx_analyzer.py`, `nid_database.py`, `generate_stubs.py`,
  `gen_hle_nids.py`, `find_functions.py`, `find_spu_functions.py`,
  `extract_spu_images.py`, `wrap_spu_elf.py`, `recomp_config.py`, plus
  audit/diagnostic scripts (`audit_boundaries.py`, `audit_fallthrough.py`,
  `objdump_audit.py`, `ghidra_lookup.py`, `oracle_diff_boot.md`).
- Depends on: the raw guest ELF/SELF and optionally Ghidra exports
  (`tools/ghidra/`, `tools/ghidra_analyze.py`) as a cross-reference oracle.
- Used by: nothing at runtime — it's a build-time/dev-time toolchain. Its output
  (`ppu_recomp_*.cpp`, `spu_recomp.c`) is consumed by the runtime library layer.
- **Not present in this checkout / gitignored:** generated `ppu_recomp_*.cpp`,
  `spu_recomp.c` for real titles, `extracted/` game data, decrypted `EBOOT.ELF`.
  Only test-generated SPU output under `runtime/spu/tests/out_*/spu_recomp.c` is
  checked in (self-contained runtime tests, not from a real game).

**Guest CPU execution model (`runtime/ppu/`, `runtime/spu/`):**
- Purpose: define the register/state model the lifted code operates on, and the
  glue between generated functions and the host process.
- PPU: `ppu_context` struct (GPR/FPR/CR/LR/CTR/FPSCR/VMX) in
  `runtime/ppu/ppu_context.h`; memory access macros in `runtime/ppu/ppu_memory.h`;
  instruction-op macros in `runtime/ppu/ppu_ops.h`; the loader/boot glue
  (`ppu_loader.cpp`) that lifted code and HLE code both depend on — ELF loading,
  `vm_read`/`vm_write`, function registry + `ps3_indirect_call`, cross-fragment
  trampoline TLS pointer, `lv2_syscall` stub, OPD resolution, `ppu_run` entry point,
  and the giant lock.
- SPU: `spu_context` struct (128×128-bit regs, 256KB local store, `image_id`) in
  `runtime/spu/spu_context.h`; channel ops + per-image function-table dispatch in
  `spu_channels.c`; DMA (MFC) engine in `spu_dma.h`; SPURS-job execution in
  `spu_workload.c`/`spu_lifted_job.h`.
- Depends on: `runtime/memory/vm.h` (guest address space), `include/ps3emu/` type
  definitions (`ps3types.h`, `endian.h`, `guest_call.h`, `nid.h`).
- Used by: generated `ppu_recomp_*.cpp`/`spu_recomp.c` (extern-C calling convention
  compiled as C++ to match), HLE library code in `libs/`.
- **Excluded from the shared static library:** `runtime/ppu/` and `runtime/host/`
  are explicitly excluded from `RUNTIME_SOURCES` in `CMakeLists.txt`
  (`list(FILTER RUNTIME_SOURCES EXCLUDE REGEX "/tests/|/runtime/ppu/|/runtime/host/")`)
  because they must be compiled per-game against that game's generated
  `ppu_recomp.h` and RSX/D3D12 backend choice — see `docs/PPU_RECOMP.md`.

**HLE firmware layer (`libs/`):**
- Purpose: reimplement ~100+ Cell OS system libraries (PRX modules) as native C,
  matched by NID rather than by recompiling the original PRX bytecode.
- Location: `libs/<category>/<cellModule>.c` — `system/` (cellSysutil,
  sysPrxForUser, cellRtc…), `filesystem/` (cellFs, cellGame, cellSaveData),
  `input/` (cellPad, cellKb, cellMouse, cellGem), `audio/` (cellAudio, cellAdec,
  libmixer, libsnd3, libsynth2), `video/` (cellGcmSys, cellVdec, cellResc,
  cellVideoOut, cellVpost, plus the RSX backend layer), `network/` (cellNetCtl,
  cellHttp(s), cellSsl, sceNp*), `spurs/` (cellSpurs, cellFiber, cellSpursJq,
  cellDaisy — SPU task management), `sync/` (cellSync, cellSync2), `codec/`
  (cellJpgDec, cellPngDec, cellGifDec, cellPamf, cellDmux, atrac3p/celp8/divx
  decoders), `font/` (cellFont, FreeType, L10n), `misc/` (screenshot, subdisplay,
  IME, video/music export, game recording).
- Depends on: `runtime/` for VM access and syscall primitives; own per-module
  headers under each `libs/<category>/`.
- Used by: NID-resolved import calls emitted by the PPU lifter into
  `ppu_recomp_*.cpp` / `gow2_gen/ppu_hle_nids.cpp`.
- Strategy is configurable per-module in `config/example.toml` `[modules]`
  (`"hle"` / `"lle"` / `"auto"`); the current example config defaults nearly
  everything to `"hle"`.

**Host backends (platform-divergent, stable contracts):**
- Purpose: give the guest-facing HLE code (cellGcmSys, movie overlay HLE) one
  stable C API while letting the actual GPU/video/audio work diverge completely
  per host OS.
- `rsx_backend` vtable (`libs/video/rsx_commands.h:323`): `init/shutdown`,
  `begin_frame/end_frame/present`, per-state-dirty setters
  (`set_render_target`, `set_viewport`, `set_blend`, `set_depth_stencil`,
  `set_color_mask`, `set_alpha_test`, `set_shader`, `set_vertex_attribs`),
  `clear`, `draw_arrays`/`draw_indexed`, `bind_texture`. Registered via
  `rsx_set_backend()` / fetched via `rsx_get_backend()`. Implementations:
  `libs/video/rsx_d3d12_backend.c` (Windows/Direct3D12, documented as the
  reference "state tracking → callback → backend" flow at the top of
  `rsx_d3d12_backend.h`), `libs/video/rsx_metal_backend.m` (macOS/arm64 native
  Metal, Objective-C, compiled with `-fobjc-arc`), `libs/video/rsx_vulkan_backend.c`
  (optional, built only if `find_package(Vulkan)` succeeds — native on Linux,
  MoltenVK on macOS as a non-preferred fallback), `libs/video/rsx_null_backend.c`
  (headless/test acceptance path — explicitly NOT accepted as "real pixels" per
  `CLAUDE.md`).
- `movie_hle_*` contract (`libs/video/movie_hle.c`): `movie_hle_start`,
  `movie_hle_start_once`, `movie_hle_from_guest`, `movie_hle_stop`,
  `movie_hle_overlay_done`, `movie_hle_autostart_cache_if_needed`,
  `movie_hle_cache_path`. The `.c` file dispatches by platform macro to three
  divergent bodies: a Windows-overlay implementation, a macOS implementation
  backed by `libs/video/movie_vt_metal.m` (VideoToolbox decode → IOSurface →
  Metal texture), and an else-branch no-op stub set.
- Audio/input backends similarly diverge in `libs/audio/` (WASAPI on Windows,
  CoreAudio ring buffer + SDL2 elsewhere — see `libs/audio/tests/test_coreaudio_ring.c`)
  and `libs/input/` (XInput on Windows, `cellpad_gamecontroller.m` GameController
  framework on macOS).
- CMake wiring: `if(APPLE)` block in `CMakeLists.txt` appends the three `.m`
  files to `HLE_SOURCES` and links Metal/MetalFX/QuartzCore/Foundation/AppKit/
  AVFoundation/CoreMedia/CoreVideo/AudioToolbox/CoreAudio/GameController/
  CoreHaptics frameworks; `if(WIN32)` links `xinput`/`ole32`/`bcrypt`/`ws2_32`.

## Data Flow

### Recompilation pipeline (offline, per game)

1. **Input must already be a decrypted ELF.** There is no SELF decryption anywhere in this repo — `grep` for AES/klicensee/NPDRM/scetool across `tools/*.py` returns nothing. `tools/elf_parser.py` parses the SELF *wrapper* (`SELF_MAGIC`, `SELFHeader` at `tools/elf_parser.py:140-180`) only far enough to locate the embedded ELF; decrypting a retail SELF is an out-of-band prerequisite handled by external tooling.
2. Parse ELF headers/segments/PRX import-export tables (`tools/elf_parser.py`).
3. Disassemble `.text` into PowerPC64 instructions, detect function boundaries
   (symbols, `blr`, call graph, prologue pattern matching), recover jump/switch
   tables (`tools/ppu_disasm.py`, `tools/find_functions.py`).
4. Lift each function into a C++ function taking `ppu_context*`, resolving NID
   imports to HLE stub calls, emitting a function-pointer registration table
   (`tools/ppu_lifter.py` → `ppu_recomp_*.cpp` + `ppu_recomp.h`).
5. Separately: extract embedded SPU ELF images (`tools/extract_spu_images.py`),
   disassemble/lift them (`tools/spu_lifter.py`) → `spu_recomp.c`/`.h`.
6. All controlled by a per-project `config/example.toml` (module HLE/LLE
   strategy, memory layout, threading, graphics backend) parsed by
   `tools/recomp_config.py`.

### Guest boot / runtime request path

1. Host `main()` (per-game, e.g. `games/gow2/boot_macos.cpp:358`) sets up the
   guest VM (`runtime/memory/vm.h`), loads the decrypted ELF's PT_LOAD segments
   into `vm_base`-relative guest memory (`runtime/ppu/ppu_loader.cpp`), zeroes BSS.
2. Resolves the OPD entry (`{u32 func, u32 toc}`) and calls into `ppu_run`
   (`runtime/ppu/ppu_loader.cpp`), which acquires the PPU giant lock and jumps
   into the lifted entry function.
3. Lifted PPU functions execute as ordinary C++ calls; PS3 library imports
   (NID-resolved) call directly into `libs/` HLE handlers, which may create host
   threads (`sys_ppu_thread.c`), touch guest memory via `vm_read`/`vm_write`, or
   call into `libs/spurs/` for SPU task dispatch.
4. RSX command buffer writes from guest code are decoded by
   `libs/video/rsx_commands.c`/`rsx_dispatch.c` into backend-agnostic
   `rsx_state`, then dispatched through the registered `rsx_backend` vtable to
   the platform GPU backend (D3D12/Metal) for actual draw submission.
5. The per-game boot loop drives `begin_frame`/`present` each frame; movie/video
   overlay is driven independently through `movie_hle_*` (own decode+present
   loop, VideoToolbox+Metal on macOS).

**State Management:**
- All guest CPU/mutable state lives in `ppu_context`/`spu_context` structs and
  the flat guest VM (`vm_base + guest_addr`); host-side runtime state (thread
  registries, lwmutex/lwcond slot arrays, HLE module state) is process-global C
  state protected only by the single giant lock described in `ppu_loader.cpp`.

## Key Abstractions

**`rsx_backend` vtable:**
- Purpose: represent one GPU draw backend behind a fixed C function-pointer
  struct so `libs/video/rsx_commands.c` never needs to know which backend is
  active.
- Examples: `libs/video/rsx_d3d12_backend.c`, `libs/video/rsx_metal_backend.m`,
  `libs/video/rsx_vulkan_backend.c`, `libs/video/rsx_null_backend.c`.
- Pattern: state-tracking layer (`rsx_state`) computes dirty flags from decoded
  NV47xx methods; callback dispatch invokes only the setters for state that
  actually changed (`libs/video/rsx_d3d12_backend.h:8`).

**`movie_hle_*` contract:**
- Purpose: one API surface for the intro/cutscene movie overlay across three
  platform implementations (Windows overlay, macOS VideoToolbox+Metal, no-op).
- Examples: `libs/video/movie_hle.c`, `libs/video/movie_vt_metal.m`.
- Pattern: compile-time platform dispatch inside a single `.c` translation
  unit (macro-gated function bodies), not per-callsite `#ifdef`.

**`ppu_context`/`spu_context`:**
- Purpose: represent the entire guest CPU register state as a plain struct
  passed by pointer into every lifted function — the "virtual CPU".
- Examples: `runtime/ppu/ppu_context.h:40`, `runtime/spu/spu_context.h`.

**Guest VM address translation:**
- Purpose: uniform `host_ptr = vm_base + guest_addr` mapping over a large
  contiguous host allocation, with big-endian-aware typed accessors.
- Examples: `runtime/memory/vm.h`, `runtime/ppu/ppu_memory.h`.

## Architectural Constraints

- **Threading:** Single giant lock serializes all guest code execution
  (`runtime/ppu/ppu_loader.cpp`, `g_ppu_giant_lock`); each genuinely blocking
  syscall (`sys_timer_usleep`, `sys_lwcond_wait`, …) must explicitly release and
  reacquire it or every other guest thread stalls. SPU workload dispatch and
  DMA (`runtime/spu/spu_workload.c`, `spu_dma.h`) run under their own
  synchronization, separate from the PPU giant lock.
- **Global state:** HLE module state (lwmutex/lwcond slot arrays, RSX backend
  pointer via `rsx_set_backend`/`rsx_get_backend`, movie overlay state in
  `libs/video/movie_hle.c`) is process-global C state, not passed through
  context objects — explicitly called out as unsafe under fine-grained
  concurrency in `ppu_loader.cpp`'s giant-lock comment block.
- **Generated code is gitignored:** `ppu_recomp_*.cpp`/`.h` and real-game
  `spu_recomp.c`/`.h` are NOT checked into this repository (except
  test-generated SPU output under `runtime/spu/tests/out_*/`, and the GoW2 NID
  table `gow2_gen/ppu_hle_nids.cpp`). Anyone exploring this repo will not find
  the actual lifted GoW2 PPU code here — it lives in the gitignored working
  tree of the sibling `../gow2-recomp` repo (see CLAUDE.md).
- **`runtime/ppu/` and `runtime/host/` are excluded from the shared static
  library build** (`CMakeLists.txt` `list(FILTER RUNTIME_SOURCES EXCLUDE REGEX
  "/tests/|/runtime/ppu/|/runtime/host/")`) — they are compiled per-game
  against that game's generated `ppu_recomp.h`, not part of
  `libps3recomp_runtime.a`.
- **Cross-fragment trampoline fallthrough:** a systematic lifter correctness
  hazard exists where a function fragment's trampoline (`g_trampoline_fn`)
  points to a guest EA numerically *lower* than the fragment's own site
  (fallthrough disguised as a forward jump) — root-caused once
  (`func_002550C8`) and flagged in CLAUDE.md as needing systematic audit across
  the whole lift.

## Anti-Patterns

### Treating the RSX null backend or overlay-only output as "pixels of the game"

**What happens:** `libs/video/rsx_null_backend.c` accepts draw calls with no
visible output; the movie overlay path can show a decoded `.m2v` intro clip
independent of the RSX/shader pipeline.
**Why it's wrong:** Neither exercises the real guest draw/shader path
(ICGLdrShader registry, CGOWShader resolution, guest textures) — accepting
either as proof of "the game renders" masks the real remaining work.
**Do this instead:** Require draws/textures to originate from the game's own
guest code through the D3D12 (Windows) or Metal (macOS) backend, per
`CLAUDE.md`'s acceptance rules.

### Copying the Windows implementation path 1:1 into the macOS backend

**What happens:** Adding a feature only via a shared abstraction implemented in
terms of Win32/D3D12 primitives, then wrapping it for macOS instead of using
native Metal/VideoToolbox/CoreAudio APIs.
**Why it's wrong:** Loses zero-copy opportunities (e.g. IOSurface→MTLTexture),
adds unnecessary staging copies, and diverges from the project's stated
optimization stance for Apple platforms.
**Do this instead:** Implement the platform-native path directly behind the
existing `rsx_backend`/`movie_hle_*` contracts (see `libs/video/rsx_metal_backend.m`,
`libs/video/movie_vt_metal.m`) — contract parity, not implementation parity.

## Error Handling

**Strategy:** Mixed — PS3 syscalls return native LV2 error codes
(`include/ps3emu/error_codes.h`); HLE module functions generally return
`CELL_OK`/`CELL_E*`-style codes matching the real Cell OS ABI so lifted guest
code's own error handling continues to work unmodified.

**Patterns:**
- Guest memory bounds violations are caught via OOB/mask tracing
  (`runtime/trace/ps3_mem_trace.c`, `ps3_mask_trace.c`), gated behind env vars,
  not by crashing the process during normal operation.
- SEH/signal isolation exists for SPU test harnesses
  (`runtime/spu/tests/test_seh_isolation_main.c`) to keep one guest fault from
  taking down the whole host test run.

## Cross-Cutting Concerns

**Logging:** Custom lightweight trace/checkpoint subsystem
(`runtime/trace/ps3_trace.c`, `ps3_checkpoint.c`), gated by `PS3_TRACE_*`/
`PS3_PERF_*` environment variables per CLAUDE.md's build/run recipes — not a
general-purpose logging framework.

**Validation:** Recompiler-config validated by `tools/recomp_config.py`
(`tools/test_recomp_config.py`); lifter correctness validated by golden-output
tests (`tools/test_ppu_lift.py`, `runtime/ppu/tests/test_ppu_lifter_emit.py`)
and disassembly/jump-table/switch-table unit tests
(`tools/test_ppu_disasm_regs.py`, `tools/test_ppu_jumptables.py`,
`tools/test_switch_tables.py`).

**Authentication:** Not applicable — this is an offline binary translator and
native game runtime, not a networked service (network HLE modules like
`sceNp*`/`cellHttps` reimplement PS3-side network APIs the game itself used).
