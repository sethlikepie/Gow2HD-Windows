# E13 — predições, escritas ANTES da corrida

**Data:** 2026-08-05 · **Antecessor:** [E12](2026-08-05-E12-pool-e-cinco.md)

## Pergunta
`idx=0` está dentro do alcance e `*(base)=5`. O descritor `r29` é o certo?

## Medido no E12 (o caso mau, 1 em 8625)
`pool=5  slot=base=0x4007FCE8  idx=0  divisor=130  r28=4  r30=1`
Aritmética: `(4 * 1*16)/130 = 64/130 = 0` → `slot = base + 0`.

## Sonda
`PS3_TRACE_POOLIDX=all` (imprime TODAS as chamadas, não só as implausíveis),
com `PS3_TRACE_FLHEAD=a`, receita menu-fast, 90 s.

## Predições
**P-1 — as chamadas sãs mostram o MESMO `divisor=130` e o MESMO `base`.**
Então a tabela é a certa e a célula 0 é que está mal populada.
→ causa #3 do probe: o defeito é de quem escreveu a célula.

**P-2 — as chamadas sãs mostram OUTRO `divisor` ou OUTRO `base`.**
Então `r29` não é o descritor certo nesta chamada.
→ causa #2 do probe: descritor errado; o alvo passa a ser quem escolhe `r29`.

**P-3 — `divisor=130` aparece SÓ no caso mau.**
Reforça P-2 e dá o sinal barato para um teste futuro: 130 não é potência de
dois, o que é raro num divisor de alocador.

**Controlo.** Tem de aparecer pelo menos uma linha `[POOLIDX]` com pool
plausível (`0x4xxxxxxx`). Se só sair a linha `MAU`, o modo `all` não pegou e a
corrida não decide nada — inconclusiva, NÃO negativa (lição do E12).
